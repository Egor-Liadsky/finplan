## Задание

Проверить дифф по списку «Что искать» из роли `reviewer` с упором на слой
application:

- `application` импортирует только `domain`, собственные `ports`, `dto`,
  `errors`, стандартную библиотеку и pydantic; нет импортов SQLAlchemy,
  aiogram, FastAPI, `infrastructure`, `entrypoints`;
- один use case — один класс с `__call__`: DTO на входе, DTO на выходе,
  транзакция открывается через Unit of Work и только в нём; нет use case,
  который пишет без `commit` или читает системные часы мимо порта `Clock`;
- деньги — только `Decimal` внутри `Money`; `float` нигде не принимается и не
  возвращается, в том числе в полях DTO; суммы в DTO не теряют валюту;
- периоды `/today` и `/month` — полуинтервал `[from, to)` в таймзоне
  пользователя по 3.1 и 6.1, включая границы месяца и перехода через полночь;
- сторно по 4.2 и абзацу «Форма сторно» раздела 3.3: исходная операция
  меняется только переходом в `reversed`, отмена — новой записью; выбор
  «последней операции, введённой в боте» не захватывает уже сторнированные
  операции и сторнирующие записи;
- остатки и итоги считают только операции со статусом `posted`;
- протоколы портов достаточны для реализации в `infrastructure` на
  подзадачах 8–9b без правки `application`: нет методов, которые
  PostgreSQL-реализация не сможет выполнить в одной транзакции под RLS
  (раздел 4.5 читать по карте, если находка его касается);
- правки документа в 2.1, 2.2 и 6.1 из этих коммитов согласованы с кодом и
  с остальным документом.

Известное и уже учтённое находкой не повторять, но оценить уровень, если он
выше записанного:

- неизвестная таймзона в `RegisterUserCommand` даёт `ZoneInfoNotFoundError`

  подзадачи 8;
- `make lint` не проверяет `mypy` каталог `tests/`; решается отдельно.

Каждую находку отнести к одному из уровней:

- **нарушение** — противоречит `docs/architecture.md` или правилу слоёв,
