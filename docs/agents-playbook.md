# Как работают агенты в finplan и почему именно так

Короткая сводка для человека: как устроена работа с субагентами, какие
правила экономии действуют и откуда взялись их числа. Обязывающие
формулировки живут в `CLAUDE.md` (раздел «Делегирование»),
`docs/tasks/README.md` и файлах `.claude/agents/*.md`; здесь — та же схема
одним взглядом. Все числа измерены по транскриптам этапа 0, разбор с методом
и расчётами — в `docs/tasks/2026-09-22-agents-protocol-audit.md`.

## Схема в пяти строках

1. Главная сессия — диспетчер и архитектор: решает, декомпозирует, пишет файл
   задачи в `docs/tasks/`, ведёт `docs/dev-log.md`.
2. Исполнитель — субагент одной роли (`developer`, `tester`, `reviewer`,
   `analyst`, `designer`), описанной файлом в `.claude/agents/`.
3. Задание передаётся только файлом задачи; результат возвращается разделом
   `## Результат исполнителя` в конце того же файла.
4. Архитектуру исполнитель читает через `docs/architecture-brief.md` — карту
   документа с номерами строк и дословные копии ключевых правил.
5. Исполнители не запускают исполнителей: вся диспетчеризация — в главной
   сессии.

## Откуда берётся цена

Модель не «помнит» разговор: на каждом обращении заново читается весь
накопленный контекст. Отсюда три следствия, определяющие все правила ниже.

- **Стоимость запуска растёт как квадрат числа обращений к модели.** По
  девяти запускам этапа 0 отношение «стоимость / вызовы²» равно 540–795, у
  сессии-диспетчера — 776. Запуск на 175 вызовов стоил вчетверо дороже, чем
  стоили бы два по 88.
- **Каждый загруженный символ оплачивается многократно.** За этап 0 новый
  текст, вошедший в контексты исполнителей, перечитывался в среднем 91 раз.
- **Почти весь счёт — это повторное чтение.** 96,3 % расхода исполнителей и
  94,1 % расхода главных сессий — перечитывание уже загруженного, а не новый
  текст.

## Правила, которые из этого следуют

| Правило | Почему, в токенах |
|---|---|
| Подзадача — до ~70 обращений исполнителя к инструментам, иначе два файла задач | дробление пяти длинных запусков этапа 0 сэкономило бы 27 554 530 |
| Сессия-диспетчер закрывается по завершении задачи, ориентир ~50 вызовов | три сессии вместо одной на 158 вызовов: 6 453 894 против 19 359 694 |
| Независимые подзадачи запускаются вместе, в одном сообщении | одно сэкономленное сообщение с запуском ≈ 116 649 |
| Исполнитель начинает с выжимки, задание называет номера разделов | 8 653 379 на чтении архитектуры и 892 199 на самостоятельной навигации |
| Ревью по `git diff`, `pytest -q`, чтение файлов кусками, `tail` для логов | множитель 91: тысяча лишних символов ≈ 44 000 токенов в середине запуска |
| Мелкая правка (до двух файлов, без нового поведения) делается без делегирования | самый дешёвый делегированный запуск этапа стоил 1 400 997 |
| Роль получает минимум инструментов | полный набор `general-purpose` дороже ролевого на ~9 400 токенов в каждом вызове |
| Тип агента проверяется до запуска | подмена роли на `general-purpose` стоила 461 000 в одном запуске |
| Прерванный исполнитель возобновляется, а не запускается заново | повторный запуск переделывает всю работу до точки обрыва |
| Запись в журнал — до закрытия сессии | состояние между сессиями живёт только в файлах |

## Что сознательно не делаем

- **Не объединяем подзадачи соседних слоёв.** Квадратичный закон работает
  против объединения: один длинный запуск дороже двух коротких.
- **Не сокращаем разделы «Результат исполнителя».** Диспетчер их с диска не
  перечитывает; экономия была бы меньше 0,04 % при потере письменного следа.
- **Не выбрасываем журнал и файлы задач.** Журнал стоил 542 000 токенов за
  этап — 0,57 % расхода — и читался в девяти сессиях из шестнадцати на
  третьем–восьмом вызове, то есть работал как задумано.
- **Не пишем выжимку руками.** `docs/architecture-brief.md` собирается
  командой `make brief` из документа: карта строится по заголовкам, правила
  копируются посимвольно, `make lint` падает при расхождении. Пересказа нет,
  поэтому второго источника истины не возникает.
- **Не переносим правила из файлов ролей в общий файл.** Выигрыш 325 550
  токенов не стоит риска размыть формулировки.

## Что это стоило на этапе 0

| Величина | Токенов |
|---|---:|
| Исполнители, 9 запусков, 911 вызовов | 68 049 388 |
| Сессии-диспетчеры, 235 вызовов | 27 445 298 |
| Весь этап | 95 494 686 |
| Из них повторное чтение контекста | ≈ 90 % |

Порядок величин полезнее точных цифр: делегирование — это не «бесплатный
помощник», а примерно два контекста, каждый из которых перечитывается на
каждом шаге. Все правила выше сводятся к одному: держать контексты
короткими, а тексты — один раз загруженными.
