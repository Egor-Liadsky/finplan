# Приведение request_id и заглушки токена к разделу 12.1

- **Исполнитель:** developer
- **Слой:** entrypoints (плюс два файла настроек репозитория)
- **Раздел архитектуры:** docs/architecture.md, разделы 12.1, 10.1
- **Заведена:** 2026-09-22

## Входные условия

Закрыты четыре подзадачи этапа 0. Точки входа написаны и проверены:
`GET /health` отвечает, middleware проставляет `request_id`, поле `service`
в логах есть. При приёмке подзадачи «Точки входа» исполнитель вернул два
вопроса, и диспетчер принял по ним решение — эта задача реализует оба
решения, других изменений в ней нет.

Прочитать до первой правки: `docs/architecture.md`, раздел 12.1
«Логирование» — там задан генератор `request_id` и написание заголовка;
`src/finplan/entrypoints/api/app.py` — текущая реализация middleware;
раздел «Результат исполнителя» файла
`docs/tasks/2026-09-21-stage0-entrypoints.md` — там описаны обе находки;
`docs/tasks/README.md` — формат раздела результата.

## Задание

**Решение 1. `request_id` — ULID, а не `uuid4`.** Раздел 12.1 называет
генератор прямо. Выбор ULID согласован с решением по первичным ключам
(UUIDv7): идентификаторы монотонны и сортируются по времени создания.
Добавить в `pyproject.toml` зависимость времени выполнения `python-ulid`
и заменить `str(uuid.uuid4())` в middleware на генерацию ULID. Значение,
пришедшее в заголовке от клиента, по-прежнему принимается как есть и не
проверяется на формат: чужой идентификатор трассировки не наше дело.

**Решение 2. Написание заголовка по документу.** Раздел 12.1 пишет
`X-Request-Id`. Заголовки HTTP регистронезависимы, поэтому поведение не
меняется, но расхождение написания кода с документом устранить: константа
`REQUEST_ID_HEADER` принимает значение `X-Request-Id`.

**Решение 3. Рабочая заглушка токена бота.** В `.env.example` значение
`TELEGRAM_BOT_TOKEN=changeme` не проходит локальную проверку формата в
aiogram 3, и `Bot()` падает `TokenValidationError` ещё до обращения к сети.
Образец окружения обязан давать работоспособный запуск, поэтому заменить
значение на синтаксически корректный фиктивный токен вида
`123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw`. Это по-прежнему заглушка, а
не настоящий токен; рядом оставить короткий комментарий, что формат обязан
быть валидным, иначе бот не стартует.

`uv.lock` пересобрать после добавления зависимости.

## Границы

- изменяются ровно четыре файла: `pyproject.toml`, `uv.lock`,
  `.env.example`, `src/finplan/entrypoints/api/app.py`;
- поведение `GET /health`, `lifespan`, CORS и проверки ревизии не меняется;
- `logging.py`, `config.py`, `infrastructure/**`, `entrypoints/bot/**`,
  `entrypoints/worker/**` не трогаются;
- `request_id` для бота (`update_id`) и для фоновых задач (`run_id`) из
  раздела 12.1 в этой задаче не реализуется: обработки апдейтов и заданий в
  этапе 0 нет, это работа этапа 1;
- `docs/architecture.md`, `CLAUDE.md`, `docs/dev-log.md` не изменяются.

## Критерий приёмки

- `uv sync` проходит, `python-ulid` присутствует в `uv.lock`;
- `uv run ruff check`, `uv run ruff format --check`, `uv run mypy src`
  проходят;
- `grep -n 'uuid' src/finplan/entrypoints/api/app.py` не находит генерации
  идентификатора запроса;
- запрос `GET /health` без заголовка возвращает `X-Request-Id`, значение
  которого — 26 символов в алфавите Crockford Base32 (проверяется
  регулярным выражением `^[0-9A-HJKMNP-TV-Z]{26}$`); фактическое значение
  привести в разделе результата;
- запрос `GET /health` с заголовком `X-Request-Id: my-id-42` возвращает в
  ответе ровно `my-id-42`;
- `uv run python -c "import os; os.environ.update(...); from aiogram import Bot; Bot(token='<значение из .env.example>')"`
  создаёт объект без `TokenValidationError`; фактический итог привести в
  разделе результата.

## Результат исполнителя

**Сделано.** Реализованы оба решения диспетчера, ровно в четырёх файлах.

`pyproject.toml`: добавлена зависимость времени выполнения `python-ulid`
(без версионного пина, как остальные зависимости в файле).

`src/finplan/entrypoints/api/app.py`: убран импорт `uuid`, добавлен импорт
`from ulid import ULID`; в `request_id_middleware` генерация заменена с
`str(uuid.uuid4())` на `str(ULID())` — значение из заголовка `X-Request-Id`
по-прежнему принимается как есть, без проверки формата. Константа
`REQUEST_ID_HEADER` переписана с `"X-Request-ID"` на `"X-Request-Id"` по
написанию раздела 12.1; больше в файле это написание нигде не жёстко
не встречается отдельно — единственное место использования константы.

`.env.example`: `TELEGRAM_BOT_TOKEN=changeme` заменён на синтаксически
корректную заглушку `123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw`; строка
комментария над переменной дополнена пояснением, что формат обязан быть
валидным (`id:hash`), иначе `aiogram` не создаст `Bot()` и процесс не
стартует.

`uv.lock`: пересобран командой `uv lock` после добавления зависимости —
добавлен пакет `python-ulid v4.0.1`.

**Решения и отложенное.**

- Версия `python-ulid` в `pyproject.toml` не пинится — в файле уже нет
  версионных ограничений для аналогичных рантайм-зависимостей (`fastapi`,
  `structlog` и т. п.), кроме тех, что явно ограничены по мажорной версии
  (`aiogram>=3,<4`, `sqlalchemy[asyncio]>=2,<3`, `pydantic>=2,<3`); `uv.lock`
  фиксирует точную версию `4.0.1`.
- `X-Request-Id` — единственное место в кодовой базе, где заголовок
  жёстко записан (через константу `REQUEST_ID_HEADER`), правка одной
  строки исчерпывает расхождение написания.
- `docs/tasks/2026-09-21-stage0-entrypoints.md` не правился — это чужой
  файл задачи, изменения фиксируются только в собственном файле задачи по
  протоколу `docs/tasks/README.md`.
